# إعادة البناء من ملف HTML المرفق — v0.3.0

اعتمد هذا التحديث على `caf_selection_tiznit (6).html` المرفق من المستخدم. استُخدمت قوالب الواجهة والشعار ودرجات الفحمي/الذهبي وخطا Cairo وPlayfair Display وتصميم التذكرة. لم تُشغّل آلية تخزينه التجريبية أو تُستورد حساباته وديونه أو مصاريفه أو كلمات المرور الموجودة فيه.

## ما تغير

- الكاشير ولوحة المالك ومعاينة الهاتف تتبع شاشات الملف: الأقسام، السلة، الدفع النقدي وعلى الحساب، تسوية الوردية بلوحة أرقام، تقرير اليوم والشهر، إحصائيات المنتجات/المصاريف/البرتقال، الندل، القائمة وبيانات WiFi للضيوف.
- `design-views.js` يحتوي قوالب عرض مقتبسة من الملف فقط. `app.js` يحول بيانات SQLite إلى نموذج العرض ويرسل التعديلات عبر preload/API المصرح بها. لا localStorage للمبيعات ولا PIN مكشوف ولا زر دخول برمز افتراضي.
- اختيار الحساب يسبق إدخال PIN، مع زر تأكيد لدعم حسابات v2 ذات رموز 6–12 رقماً، دون تغيير رموز المستخدمين الحاليين. يمكن للنادل استعمال PIN من 4–12 رقماً وفق إعداد المالك.
- لا تستخدم الواجهة eval أو Function أو تنفيذ onclick نصي. تُحوّل قوالب الأحداث إلى مستمعات محدودة بقائمة وظائف معتمدة، مع CSP وعزل Electron. تُهرب أسماء المنتجات والعملاء والملاحظات قبل إدراجها في HTML.
- Tailwind مجمع محلياً في `design.css`، والخطوط وFont Awesome في `assets/` مع تراخيصها. لا CDN ولا Google Fonts وقت التشغيل. لإعادة تجميع CSS بعد تعديل القوالب: `cd electron_pos && npm run styles`.
- بيانات التشغيل القديمة محفوظة. يُضاف حقل أرشفة للحسابات فقط عند فتح قاعدة قديمة. أرشفة النادل تمنع دخوله وتخفيه من قائمة الطاقم وتبقي اسمه وطلباته وتقاريره محفوظة. لا تُؤرشف الحسابات قبل إغلاق الورديات وتأكيد استلامها.
- قاعدة الملف «وردية نادل واحدة مفتوحة» مطبقة داخل الخدمة، حتى مع جلسة أخرى سبق تسجيل دخولها. تُسمح معالجة الورديات المتعددة الموروثة من v2 بالدخول لأصحابها لإغلاقها، دون قبول مبيعات جديدة أثناء التعارض.
- زر استيراد القائمة يأخذ الأقسام والمنتجات العشرين وأسعارها فقط من الملف، دون استبدال المنتجات القائمة أو إنشاء أي حركة مالية. راجع الأسعار قبل اعتمادها.
- بيانات شبكة الضيوف اختيارية ويُقصد مشاركتها على التذاكر؛ لا تُدخل فيها كلمة مرور شبكة الإدارة أو حساباتك. PIN منفصل ومحمي بتجزئة scrypt.
- معاينة Android داخل HTML تتطلب دخول المالك، ولا تعطي النادل صلاحيات المالك، ولا تدعي اتصالاً بهاتف فعلي. تطبيق Android الأصلي مستقل في `mobile_owner/`، وتم تحديث هويته وخطوطه وشعاره لتطابق الملف. الربط الحي ما زال يحتاج إعداد Supabase وFCM كما في دليل v2.

## التشغيل والتحقق

اتبع [دليل التشغيل](SETUP-V2.md). نسخة Windows تستخدم نفس ملف `cafe-v2.sqlite`؛ لا تغير مسار البيانات. نسخة المتصفح `npm run preview` تستخدم SQLite مستقلة للمعاينة على `http://127.0.0.1:4173`، وليست مجرد فتح index.html من القرص.

`npm test` يفحص المنطق والصلاحيات والمزامنة؛ `node test/browser.cjs` يفحص مسار إعداد المالك واستيراد القائمة وإضافة نادل وزبون ومصروف، البيع النقدي وعلى الحساب، WiFi في التذكرة، إغلاق وتأكيد الوردية، معاينة الهاتف والتقرير الشهري. يتأكد أيضاً من عدم طلب خطوط/أيقونات خارجية وعدم ظهور PIN. بيانات الاختبار مؤقتة ومعزولة عن المقهى.

معاينة الشكل الفعلي في `docs/html-pos.png` و`docs/html-owner-split.png`. بناء Windows يفحص أيضاً تشغيل Electron الأصلي وتوليد PDF. Android يُفحص بـTypeScript وMetro وبناء APK؛ لا يدّعي ذلك تجربة هاتف أو طابعة حرارية فعلية.
